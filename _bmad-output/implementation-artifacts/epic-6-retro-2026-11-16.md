## Findings

Dispositions: fix now / defer / accept. "Prevention" is the upstream lesson.

### Behavior and spec-to-implementation (highest value)

1. **Schema upgrade never runs on existing databases (6-3).** `init_db` carries `ALTER TABLE player_props ADD COLUMN IF NOT EXISTS recent_outcomes JSON` (`services/worker/parlaypal_worker/db.py:83-87`, commit `41614c7`), but `_ensure_schema_initialized` only calls `init_db` when a table is missing (`ingestion.py:1835-1840`). A Postgres volume created before 6-3 therefore keeps the old schema and every `sync_live_slate` cycle fails with `column player_props.recent_outcomes does not exist` (worker log, 2026-11-16 15:45; repeated every 30 seconds). Observed on the human's first local run; fixed locally with the same idempotent `ALTER`, and a model-vs-database drift check then reported no drift. **Disposition: fix now.** **Prevention:** the deferred 6-3 ledger entry only asked for a test of the ALTER branch; the real gap was that the branch is unreachable for existing databases. Migration-bearing stories need an upgrade-path test against a database created by the previous version.
2. **Local startup is undocumented and collides across worktrees.** `docker-compose.yml` hard-codes `container_name: parlaypal-postgres` / `parlaypal-redis` with no project `name:`, so running compose from a worktree folder created a different project and failed with a name conflict (session, 2026-11-16). Celery on Windows needs `--pool=solo`, which is written nowhere in the repo. **Disposition: fix now.** **Prevention:** a story that ships a runnable service should ship its run instructions.
3. **Spec drift in planning artifacts (reconcile).** `epic-6-context.md` lists stories 6.1-6.6 and no 6.7 (33 lines, no match for "6-7"/"6.7"). `epics.md:426` still lists the Carson Beck "Under 11.5 Rush Yds" open question, but `spec-6-6-preset-candidate-quality-gate-dedup.md:34` already decided it ("valid market; no special-casing"). The 6.5 deferred ledger entry ("Choose and wire a real player game-log source") is satisfied by 6-7 but is not marked resolved. **Disposition: fix now (human applies; spec reconciliation is proposed, not applied).**
4. **6-7 as-built vs spec.** All frozen constraints and matrix rows are covered by tests (399 worker tests pass). Accepted deviations, recorded so later runs stop re-flagging them: roster is cached page by page rather than as one name-to-id map (spec Design Notes state this); empty game logs are cached for the full 20 hours rather than the 15-minute negative TTL (Review Triage Log row 1, avoids re-polling players with no games); the frozen "Never" list keeps `player_anytime_td` unsupported. **Disposition: accept.**
5. **Cross-story boundary 6-5 to 6-7.** `resolve_game_logs` (6-5) now carries a `use_moneyline` flag and a `MoneyLineDeferred` branch in the same loop (`game_logs.py`), and `game_logs` newly imports `moneyline` (no cycle: `moneyline.py` imports neither `game_logs` nor `ingestion`). ### Process findings (session record)

6. **Provider chosen before a probe.** 6-7 was specced against api-sports.io with a human-gated paid-plan check as Task 1; a free-tier MoneyLine probe (about 130 credits across the session) then showed current NBA/NFL coverage, 1-credit game logs and a 99% NBA name match, forcing a frozen-intent renegotiation (spec Change Log, 2026-11-16) and a file rename. The probe also found preseason rows in NBA logs that would have corrupted hit rates. **Prevention:** run a cheap coverage probe before freezing an external-provider spec.
7. **Worktree created from a stale remote ref.** The 6-7 build worktree was based on a pre-merge `origin/main` and lacked the just-merged spec, needing a fast-forward (session, 2026-11-16). **Prevention:** `git fetch` before creating a worktree.
8. **`git_flow.py ship` always pushes; `bmad-build` forbids auto-push.** `git_flow.py` exposes only `start`, `ship`, `sync`, `install-aliases`, so a local-only commit needs plain git, which `AGENTS.md` discourages. **Prevention:** add a commit-only subcommand.
9. **Review layers need subagents.** `bmad-build` step 4 launches three context-free reviewers; with no standing permission for subagents, 6-7 received an inline self-review only. The self-review still found one medium defect (credit burn from re-polling empty logs), fixed before merge. **Prevention:** decide whether to grant standing permission once per workflow run.
10. **Sprint status is a shared mutable file.** 16 of the epic's 31 commits touch `sprint-status.yaml` (`git_evidence.py`), and two merge commits only sync `main` into story branches ("Merge origin/main into fix/6-1...", "merge: sync main into 6.7 spec branch; mark 6.5 done"), consistent with contention on that file (the commit messages do not say it was the cause). **Prevention:** update status only on `main` during the accept chore.
11. **Review traceability.** Specs 6-2, 6-3 and 6-4 have no Review Triage Log rows although their reviews left entries in `deferred-work.md`; the ledger is the only record. **Disposition: accept; note that triage evidence for those three lives in the ledger.**
